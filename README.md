# PROJECT PULSE — GOD EDITION

Capri AI is a responsive, same-origin web application with a Node.js backend. The browser never receives an AI provider key. Conversations, preferences, tasks, notes, and memories are stored per account in SQLite.

## Requirements

- Node.js 20 or newer
- npm
- A Groq API key for actual AI responses (optional until configured)

## Run locally

```sh
npm install
cp .env.example .env
# Set GROQ_API_KEY in .env on the server only
npm start
```

Open `http://localhost:3000`. Create a user account through the app. The chat is deliberately unavailable until the server has a Groq key; it does not pretend that canned replies are generated by an AI.

For production, set `NODE_ENV=production`, `SESSION_COOKIE_SECURE=true`, and serve the app behind HTTPS. Configure `DATABASE_PATH` to a persistent, access-restricted volume. Back up the SQLite database. Do not commit `.env`, database files, provider keys, or passwords.

## One-time administrator bootstrap

Set a long, random `ADMIN_BOOTSTRAP_TOKEN` in the deployment environment, then submit a one-time request from a trusted machine. The token is accepted only before the first admin exists:

```sh
curl -X POST http://localhost:3000/api/admin/bootstrap \
  -H 'Content-Type: application/json' \
  -H 'X-Admin-Bootstrap: YOUR_BOOTSTRAP_TOKEN' \
  -d '{"email":"admin@example.com","password":"use-a-long-unique-password"}'
```

The bootstrap endpoint is disabled if the token is unset or an admin already exists. Remove the bootstrap token from the environment after setup. Admin routes require an authenticated admin session; provider secrets are configured only through server environment variables, never the admin UI.

## What currently works

- Account registration/login, password hashing with scrypt, HTTP-only same-site sessions, CSRF checks, logout, and account-scoped APIs.
- Persistent conversations with search, rename, delete, recent message context, and Groq streaming through a server-side provider adapter.
- Persistent user preferences, short/long memories, tasks, and notes.
- Browser-local calculator, file text extraction for supported text files, conversation export, speech input/output where the browser supports those APIs, and responsive UI themes.
- Protected admin overview and user disable controls, plus server-side audit events.

The Groq provider, database persistence, and authenticated sync require deployment configuration. File analysis reads selected text files in the browser; it does not upload documents. Audio transcription is browser-provided speech recognition, not an AI provider feature. This initial version does not claim email verification, password reset, billing, multi-region sync, encrypted-at-rest user fields, or enterprise identity management.

## API and security notes

The server uses same-origin routes, Helmet headers, a JSON request-size limit, rate limits, per-user ownership checks, CSRF tokens, random opaque sessions stored hashed in SQLite, and parameterized SQL. Passwords are salted and hashed with scrypt. Configure HTTPS and a persistent database volume in production. For public commercial deployment, add operational monitoring, backup/restore drills, email verification and account recovery, stronger distributed rate limiting, and a production session/database strategy appropriate to expected scale.

AI routes: `POST /api/chat` streams server-sent events (`start`, `delta`, `done`, `error`). The `GROQ_API_KEY` is read only from the server environment. A future provider can implement the same provider boundary without putting credentials in frontend code.

Run automated backend tests with:

```sh
npm test
```
